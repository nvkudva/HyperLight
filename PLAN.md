# Architecture and Decisions

## Core Architecture
- Local-first multimodal search and question answering pipeline on macOS (Apple Silicon).
- Multimodal indexing (text + images) using CLIP/SigLIP for unified semantic vector space.
- Local LLM inference using Gemma 2 (via local Ollama engine) for private question answering and synthesis with citations.
- Embedded vector database using LanceDB for zero-server, fast disk-backed vector storage.
- File scanner supporting documents (PDF, TXT, MD, DOCX) and photos (JPEG, PNG, HEIC, WebP) with metadata extraction.
- Connectors for local disk paths, Google Drive sync folders, and Google Photos takeout/sync paths.
- Two user surfaces: Command Line Interface (`hyperlight`) and interactive local Web UI (FastAPI).

## Constraints
- Privacy: All embeddings, queries, and file processing happen locally on device.
- Low latency: Precomputed embeddings stored in LanceDB; Apple Silicon MPS/Metal acceleration for inference.
- Minimal dependencies and clean codebase structure without unnecessary abstractions.

## Rejected Alternatives
- Cloud vector databases (Pinecone, Weaviate Cloud): Rejected because personal search data must remain private and local.
- Server-based local vector DB (Milvus, Qdrant in Docker): Rejected in favor of embedded LanceDB to avoid daemon setup overhead.
- Dual separate embedding models for text vs images: Rejected in favor of unified multimodal embedding space (CLIP/SigLIP) so cross-modal search ("Find photo of my kid eating ice cream") works directly without captioning bottlenecks.

## Revisions
- Chat-first UI layout: Main workspace structured as an conversational AI chat interface with message bubbles, inline photo galleries, and collapsible source citations.
- Settings view separation: Folder management, Google Drive/Photos directory configurations, and database controls moved into an accessible modal/page rather than cluttering main search view.
- Folder addition refinement: Native macOS Finder folder picker via AppleScript, automatic discovery of Google Drive and Google Photos sync paths, persistent configured sources registry, and 1-click preset cards.
- Background Indexing & Progress Control: Detached background worker thread executing scans independently of client UI session, supporting real-time percentage progress bars, user-initiated cancellation, and rescan capability.
- Metadata-Aware Indexing and Intent-Based Retrieval: Files capture rich metadata including file size, file type, creation date, and modified date. Gemma 2 context is injected with structured metadata so it answers queries about file types, sizes, and dates. Stricter photo intent matching prevents visual searches from returning random image files on metadata queries.
- Next-Gen Siri/Spotlight Replacement Architecture: Unified multi-domain personal ontology covering 7 personal facets (Files & Code, Photos & Screenshots, Notes, Calendar, Contacts, Web History, Communications). Hybrid retrieval coupling dense multimodal embeddings (OpenCLIP/SigLIP) with lexical keyword indexing (BM25/FTS) and Gemma 2 on-device reasoning.
- Native macOS System Connectors: Automated ingestion of installed macOS applications (/Applications, /System/Applications), Safari bookmarks/reading list, and standard macOS entity paths.
- Spotlight Floating HUD Interface: Quick-access Spotlight modal overlay with instant keystroke-level filtering, categorized entity groupings (Apps, Contacts, Events, Docs, Photos), keyboard shortcuts, and inline Gemma 2 synthesis.
- Multi-Category Candidate Reranking & Dynamic Clean-Up: Expanded candidate retrieval pool in hybrid search with per-category distribution caps, ensuring cross-domain representation (Apps, Contacts, Events, Docs) without single-domain starvation. Added dynamic path-based record removal from LanceDB when sources are detached.
- Scanning Acceleration Pipeline: Eliminated per-file LanceDB write transactions with chunked batch inserts (60x faster), added batched image tensor inference on Apple Silicon MPS (14x faster), implemented directory traversal pruning (skipping .git, node_modules, .venv), capped huge text dumps to 500KB, and introduced incremental mtime caching so rescans complete in single-digit milliseconds.
- Multi-Threaded Parallel File Extraction: Implemented concurrent worker pool (ThreadPoolExecutor) across all CPU cores for I/O-bound and CPU-bound parsing (PDF, DOCX, text files, vCards, calendars, and image decoding), pipelining extracted chunks directly into GPU batches.
- Zero-Copy Arrow Storage & Kernel Direntry Acceleration: Integrated direct pyarrow.RecordBatch and pyarrow.Table construction for zero-copy C++/Rust batch inserts into LanceDB (3.5x faster writes). Replaced recursive traversal with iterative APFS stack crawler using os.scandir direntry attribute caching (skipping separate stat syscalls), and added libjpeg-turbo IDCT scale-down draft decoding for high-res photos.
- Native macOS FSEvents Live Background Watcher: Integrated kernel-level FSEvents subsystem (via watchdog FSEventsObserver) to continuously monitor configured directories without polling or battery drain. Newly created or modified files are automatically indexed in <15ms with 0.5s debouncing, and deleted files are cleanly pruned from LanceDB in real time, reducing user scan wait time to zero.
- Asynchronous Non-Blocking Logging Architecture: Replaced blocking disk loggers with Python QueueHandler and background QueueListener writing to ~/.hyperlight/app.log. All search queries, file indexing, and system calls log in sub-millisecond time without stalling FastAPI event loops or worker threads.
- macOS Liquid Glass UI System: Re-architected presentation layer with macOS Sequoia Apple Glass design system (frosted backdrop-filter, SF Pro typography, dynamic specular lighting, and traffic light window controls). Tailored entity-specific renderers for Photos (masonry/lightbox), Documents (metadata badges), Contacts (vCard info), Calendar (event cards), Safari Bookmarks (domain favicons), and Applications (launch badges).
- Native Finder Context Menu & Volume Discovery: Integrated macOS Finder interactions with custom right-click context menu (open -R Reveal in Finder, default app launch, path copy). Added automated discovery for mounted SMB/NFS network shares in /Volumes and Google Drive CloudStorage mounts in ~/Library/CloudStorage.
- Native Swift Cocoa / WebKit macOS App Wrapper: Packaged Hyperlight as a compiled native macOS desktop application (Hyperlight.app) using Swift 6.4 with NSVisualEffectView behind-window vibrancy and transparent WKWebView container, featuring standard macOS window controls and native Edit/View menu shortcuts.
- Apple HIG Minimalist UX Polish: Eliminated redundant instructions, fake CSS window chrome, and duplicate action buttons. Streamlined navigation into a native-feeling macOS sidebar, unified search omnibar with subtle ⌘K shortcuts, minimalist hero suggestion chips, and compact hover-revealed action pills across all entity cards.
- macOS 27 Apple Glass Specular Iconography System: Fully migrated from legacy emoji characters to native SF Symbol-grade hairline vector SVGs (stroke-width: 1.8px) housed in frosted continuous-curvature squircle badges with specular inner-lighting (`box-shadow: inset 0 1px 0 rgba(255,255,255,0.95)`). Unified icon language across Applications, Documents, Photos, Contacts, Calendar, Web Bookmarks, and System Settings.
- Native WebKit UI Delegate & Resilient Connected Sources Management: Conformed Swift native wrapper `AppDelegate` to `WKUIDelegate` with native Cocoa `NSAlert` modal panels, eliminating silent WKWebView dialog drops. Replaced blocking browser dialogs with non-blocking inline toast notifications (`#settingsToast`), introduced a direct manual path input bar for custom folders and network mounts, normalized symlinked APFS paths across storage and watcher operations, and added an automatic Finder folder picker fallback when Google Drive CloudStorage mounts are not auto-detected.
- Cloud Google Account Integration (Google Drive & Photos): Implemented Google OAuth 2.0 authorization, token exchange, and automatic token refresh supporting standard Google scopes (drive.readonly, photoslibrary.readonly, userinfo.profile, userinfo.email). Added cloud sync workers for Google Drive v3 REST API and Google Photos Library v1 REST API with in-memory image embedding, cached previews, and real-time progress reporting. Built a frosted Apple Glass Google Account UI with quick Mac account linking, Sign in with Google, custom OAuth credentials configuration, and Sync Drive/Photos controls.
- Modular React UI Architecture with CSS Modules: Replaced monolithic single-file HTML/JS prototype with a componentized React 19 + TypeScript + Vite architecture using CSS Modules (*.module.css) for scoped styling. Decomposed interface into isolated components: Sidebar, ChatWorkspace, SpotlightHud, SettingsSheet, GoogleAccountCard, ContextMenu, and PhotoLightbox. Configured Vite build pipeline outputting to frontend/dist, served directly by FastAPI on port 8585 inside the native Swift WKWebView container.
- EmbeddingGemma 2 Migration: Replaced OpenCLIP ViT-B-32 with Google DeepMind's EmbeddingGemma 2 (768-d multimodal vector space) with asymmetric task prompts (`task: search result | query: ...` and `title: ... | text: ...`), 2048-token context, and LanceDB 768-d schema upgrade.
- Advanced Search Refinements: Integrated cross-modal score calibration (centering by modality mean to balance photos and text), statistical z-score relevance gating, adaptive lookup weighting for error codes/IDs, page image rendering fallback for scanned PDFs, and Apple Vision OCR keyword extraction for screenshots without vector pollution.

- Google OAuth: Use the user's own "Desktop app" OAuth client, pasted as JSON. Rejected: borrowing gcloud's ADC client, because Google blocks it for Drive, Gmail and Photos scopes and for custom redirect URIs.
- Google Photos: Use the Photos Picker API, where the user picks items for each session. Rejected: photoslibrary.readonly, which Google restricted in March 2025 to app-created media only.
- Apple Mail: Index ~/Library/Mail .emlx files through the normal scanner pipeline, which requires Full Disk Access. Rejected: AppleScript/Mail.app automation, which is slow and needs Mail running.
- Index jobs: Run them sequentially from a queue in IndexJobManager, so onboarding can submit every source at once.
- Onboarding is local-first: Mac folders, Apple Mail, and Google Drive through Drive for desktop. Google API sign-in is optional and lives in Settings. Rejected: making the Drive API the default route, because it needs a Google client plus restricted-scope verification.
- Cloud-only files (SF_DATALESS) are indexed by name and folder only. Rejected: reading their content, because that would download the whole cloud drive.
- UI colors come from CSS tokens in index.css (Apple system palette, light and dark). Hard-coded hex values are not allowed in components; Google brand logo colors are the only exception.
- Window glass is native: the window is transparent and window-vibrancy applies Liquid Glass, falling back to NSVisualEffect Sidebar before macOS 26. In Tauri the window and sidebar backgrounds are transparent and the content pane is opaque, because glass belongs to controls, not content. Rejected: glass drawn only with CSS backdrop-filter, because it blurs only the app's own pixels.
- Cross-platform UI library: Konsta UI if mobile builds are added. Rejected: Ionic, which looks like a phone app on desktop; React Native, which means a rewrite.
- Google v1 ships one app-owned Desktop OAuth client (google_client.json beside google_auth.py, gitignored) and requests only photospicker + profile/email. Drive comes from Drive for desktop and Gmail from Apple Mail (Internet Accounts). The Drive and Gmail API scopes stay behind HYPERLIGHT_GOOGLE_FULL_ACCESS=1 until verification and CASA are done. Rejected: users pasting their own OAuth client JSON, because it needs a Google Cloud project per user.
- Two screens: Search (compact window, live results with preview, ⌘↩ hands the query to chat) and Chat (full window, sidebar of saved conversations, Settings as a page). ⌘K switches to Search, ⌘N starts a chat, ⌘, opens Settings. The window resizes between 780×520 and 1140×780. Rejected: keeping a Spotlight overlay on top of chat, because it duplicated search.
- Chat history lives in localStorage (key "conversations") on the frontend. Rejected: a backend store for v1, because the history is single-user and needs no sync.
- Index progress is polled continuously (1 s while running, 3 s idle), so a scan started from anywhere shows the scanning pill. The pill opens Settings > Indexing for details.
- Tauri shell is split into `hotkey.rs` (listen-only CGEventTap, Input Monitoring, re-enables itself after macOS disables it), `backend.rs` (starts the backend off the main thread) and `lib.rs` (wiring). The window opens at once and navigates to http://localhost:8585 when the backend answers. Rejected: blocking launch until the backend is healthy (up to 60 s with no window), and Accessibility-level taps (not allowed in the App Sandbox).
- The local API is unauthenticated, so `web_app.reject_foreign_requests` rejects foreign Host headers (DNS rebinding), foreign Origins, and cross-site subresource requests. Top-level GET navigations stay allowed for the Google OAuth redirect.
- Frontend API calls go through `api.request`, which throws `ApiError` (with the backend's `error` as `code`) on non-2xx responses. Rejected: callers checking `res.error` one by one, because most of them forgot.
- Distribution: Developer ID + notarization first. The Mac App Store needs the App Sandbox, a bundled Python sidecar, security-scoped bookmarks instead of free path access, no Full Disk Access (Apple Mail), no Ollama dependency and no `macOSPrivateApi`. Each of these is a separate project.
- System Settings indexing: curated pane catalog (name, keywords, x-apple.systempreferences: URL) embedded as type `setting` alongside apps, surfaced in its own Spotlight bucket, click opens the pane. Rejected: reading live setting values or flipping toggles, because macOS has no public API for either and per-setting defaults/AppleScript hacks are fragile.
- Settings toggle investigation (for later per-setting actions): Siri flips switches through Apple's private system intents backed by Settings intent extensions, with no public generic toggle API for third parties. Viable per-setting routes are AppleScript scripting dictionaries (dark mode verified scriptable on this Mac: System Events, appearance preferences, dark mode boolean), Apple-shipped Shortcuts actions run via `shortcuts run`, and `defaults write` for plist-backed preferences (often needs an app restart). Rejected: Accessibility UI clicking to flip switches, because it needs Accessibility permission and breaks on any Settings UI change. Decision for now: opening the correct pane is good enough; actions come later with user confirmation before execution.
- iCloud Drive: index the local CloudDocs folder (~/Library/Mobile Documents/com~apple~CloudDocs) through the normal scanner as source type `icloud_drive`, same local-first pattern as Drive for desktop. Cloud-only dataless files stay name-only per the SF_DATALESS rule, so indexing never downloads the drive. Rejected: CloudKit/iCloud API access, because it needs an app-specific container and cannot read the user's Drive files.
- Superseded: the native Swift/WKWebView wrapper is replaced by the Tauri shell, and the legacy single-file `templates/index.html` UI is removed; FastAPI serves only `frontend/dist`. The OpenCLIP mentions above are superseded by EmbeddingGemma 2.
- Index version marker: `storage.INDEX_VERSION` (model + vector size) is written beside the LanceDB table. A mismatch logs a warning and rebuilds the index, because vectors from different models are not comparable.
- Source runners: `sources.RUNNERS` is the one registry of non-folder sources (Drive, Photos, Gmail, Apps, Settings) and their fixed paths; jobs, routes and the frontend key off `runner` instead of sniffing paths. Item counts are read live from the index, not stored in config.
- Ranking: score = cosine similarity minus the item's mean similarity to fixed meaningless queries (`ranking.NULL_QUERIES`), gated by an absolute per-modality floor. EmbeddingGemma similarities are compressed (gibberish and real queries both top out near 0.66), so the old relative z-score gate always let something through; hub items (long JSON, minified JS, generic photos) matched everything. Rejected: corpus-centroid correction, because it separated gibberish from real queries worse in testing. Query words skip stopwords and result-kind words ("photos") and match at word starts.
- Index exclusions: `parsers.is_indexable` drops machine-generated files (tokenizers, lockfiles, `.min.js`, hashed bundles); scanner and watcher indexes only `originals/` inside a `.photoslibrary`, because derivatives duplicate every photo. Spotlight dedupes by filename + byte size.
